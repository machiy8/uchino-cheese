## 0. 要約
- 相棒は1体。**最初の熟成の結果がそのまま「うちの子」になる**（育て方でタイプが変わる＝オーナーの「育て方で変わる」をペット側でも実現）
- 状態は6つ：機嫌・なつき度・元気・段階・一緒に過ごした日数・着せ替え（＋放置で出る「すね」「ワイルド度」）
- 毎日の操作は7つ。1日の合計は2〜5分で上限に届く設計（ねこあつめ・なめこの「1日数分」）
- 放置しても失うものはない。すねる→2回なでれば直る。カビがふわふわ増える（ワイルド化）→お手入れで戻る。**戻ってきたら「再会ボーナス」でむしろ得をする**
- 卒業（殿堂入り）しても消えない。飾り棚に住み続け、いつでも相棒に戻せる
- **v2**：相棒は**図鑑のレシピを教えてくれる係**（ひらめき 1日2〜4個）で、**なつくほど熟成が早くなる**（最大10%）。**名前を付けられる**（初期名「うちの子」）

### 1-1. 段階のしきい値（企画補足の期間に合わせる）
| 段階 | 一緒に過ごした日数 | 変化 |
|---|---|---|
| うまれたて | 1日目 | まるい・白っぽい・目が開いたばかり。表情は3種 |
| 若チーズ | 2〜14日目 | 表情5種に。好き嫌い（温度・手入れ）が見えはじめる |
| 食べごろ | 15〜60日目 | 一番可愛い時期。性格が固まり口癖が増える。着せ替えの全スロット解放 |
| ヴィンテージ | 61日目〜 | 色が深くなる・貫禄パーツ。口癖が渋くなる。殿堂入りの選択肢が出る |

**暦の日数ではなく「一緒に過ごした日数」で進める**理由：放置中に勝手に大人にならない＝「待っていてくれた」体験にする。戻らない人を責めない設計と整合する。

## 3. なつき度による熟成短縮（v2 新設・オーナー決定 2026-10-12 #5）

### 3-1. 決まり
- 図鑑用の熟成（熟成棚）の**段階のしきい値**を、仕込んだ時点のLvの%だけ短くする。Lvと%は §1-2（Lv4〜5＝3%、Lv6〜7＝5%、Lv8〜9＝7%、Lv10＝10%、Lv1〜3＝0%）
- **仕込んだ時点のLvで固定**し、熟成棚の枠に `boostPct` として保存する。熟成中にLvが上がっても、その枠の時間は変わらない
  - 理由：①取り出しの「窓」（例：1日たってから3日になる前）が熟成中に前へずれると、ねらった段階を通り過ぎるおそれがある ②熟成完了の通知を仕込み時に1回だけ予約すればよい（OS のローカル通知は予約の付け替えが手間）
- 計算は**整数（分）**：`短縮後のしきい値（分）＝ 名目（分）×(100−短縮%) ÷ 100` の**分未満切り捨て**
  - 切り捨ての理由：プレイヤーに有利な側（早く届く）に倒す・表示が分で割り切れる
- 取り出したときの段階：`経過分＝(取り出し時刻−仕込み時刻) を分単位で切り捨て`、`段階＝経過分 ≥ 短縮後のしきい値 となる最大の段階`。窓の上の端（次の段階のしきい値）も同じ%で短くなる
- 相棒の段階・一緒に過ごした日数・機嫌などには効かない（熟成棚だけ）
- リワード広告の時短（別仕様）と併用できる：短縮後のしきい値に対して、広告が経過時間を進める（足し算）

## 4. 相棒の名前（v2 新設・オーナー決定 2026-10-12 #6）

| 項目 | 仕様 |
|---|---|
| 初期名 | 「うちの子」（世界観の呼び方。decision-log 2026-10-08） |
| 変える場所・回数 | 相棒の画面で名前をタップ → 入力。**何回でも・無料**。「うちの子に戻す」ボタンあり |
| いつ聞くか | 最初の相棒が生まれた直後に1回だけ「名前をつける？（あとで変えられるよ）」と聞く。スキップすれば「うちの子」のまま |
| 文字数 | **1〜8文字**（見た目の1文字＝書記素で数える）。理由：ひらめきの見出し「{名前}のひらめき」・記念撮影の帯・飾り棚の札に1行で収まる長さ |
| 使える文字 | ひらがな・カタカナ・漢字（U+4E00〜U+9FFF と「々」）・英字・数字・「ー」「・」「〜」「♪」「☆」「！」「？」 |
| 使えない文字 | 絵文字・空白・改行・制御文字・上記以外の記号。理由：記念撮影の画像合成（Canvas）で使うフォントに無い字が「□」になるのを防ぐ。**漢字もフォントに無い字は保存前に弾く**（ビルド時に同梱フォントの字の一覧を作り、それで照合） |
| 正規化 | 入力をNFKC正規化（半角カナ→全角、全角英数→半角）。前後の空白は自動で取る |
| NG語 | 端末内のNG語辞書（JSON・アプリに同梱・アップデートで差し替え）で照合。照合用の形：NFKC→カタカナをひらがなへ→英字は小文字→「ー・〜♪☆！？」を除いた形。**3文字以上の語は部分一致、2文字以下の語は完全一致**（短い語の部分一致は普通の名前を誤って弾くため）。当たったら「その名前はつけられないよ」とだけ出す（どの語に当たったかは見せない） |
| NG語の中身 | ①性的な語 ②差別語 ③暴力・自傷をあおる語 ④運営を装う語（公式・運営・管理者・サポート 等）。辞書は自社で作る（他社の辞書を写さない）。初版は約200語を目標に、チーズくんが案を作りdの確認後に同梱（**d決定 2026-10-12**：初版はチーズくん作成・d確認）。**初版案＝`work/ng_words_v1.txt`（2026-10-14・d確認待ち）**。照合の検査は `work/ng_check.py`（図鑑82種の名前と、ありふれたペット名で誤って弾かないかを確かめる） |
| NG語の印（案・d確認待ち） | 上の「3文字以上は部分一致・2文字以下は完全一致」だけだと、**漢字2文字の「運営」「公式」が完全一致になり「運営です」を通してしまう**。辞書の行頭に `*` を付けた語は長さに関係なく部分一致、`=` を付けた語は長さに関係なく完全一致、とする印を足す案（`ng_words_v1.txt` の冒頭に説明）。採らない場合は `*`・`=` を外せば元の規則どおりに動く |
| 外に出るか | 名前は端末の中だけ（サーバーなし）。出るのは本人が保存・共有した記念撮影と卒業証書の画像だけ |
| 写真に出すか | 設定「写真に名前を入れる」（既定：入れる）。オフなら画像の名前の欄に「うちの子」も出さず空ける |
| 殿堂入りの子 | 名前を持ったまま飾り棚へ。飾り棚でも変えられる |
| 通知 | 通知文には名前を入れない（ロック画面に出るため。相棒が一人称で話す文のまま） |
| 工房主・案内役 | 名前の仕組みは相棒だけ。工房主（差し替えスロット・ウーパーちゃん案）とは別 |

## 5. ヒントを相棒が話す（v2 新設・`ヒント設計_v1.md` との接続）

### 5-1. いつ話すか（ひらめき）
| 場面 | 条件 | 話す内容 |
|---|---|---|
| その日最初の「話しかける」 | Lv1〜。すね中は、すねが解けた後の最初の1回 | ねらいのカードの次の穴（ひらめき①） |
| 「おはよう」 | Lv1〜。前の晩に寝かせた翌朝 | ひらめき② |
| 好きな方の「日向ぼっこ／ひんやり」 | Lv4〜。その日1回目 | ひらめき③ |
| その日最初の「お手入れ」 | Lv7〜 | ひらめき④ |
| 再会（3日以上あいて戻った） | 1日1回 | ヒント1つ（§2-1） |
| 熟成棚から取り出したとき | 毎回 | 登録・失敗の解説・近さのしるし・なかまのヒント・タイプのきほん（`ヒント設計_v1.md` §3・§5） |

- 1日のひらめきは Lv の数まで（§1-2）。**持ち越さない**（その日の習慣で受け取るもの）。ただし「はじめてのレシピ帳」（2〜8日目）は休んでも翌ログインで受け取れる
- 開ける穴が無いときは、登録済みチーズのまめ知識（一言解説）を話す

### 5-2. 言い方
- ヒント文は `zukan_tools/out/hints.json` の `cards[].hints[穴]`（中立の文「◯◯のレシピは、〜みたい」）を、**相棒のタイプ別の口調の型**（`wrap`：9タイプ×2通り）で包んで出す。例：相棒が青カビなら「べ、べつに教えたいわけじゃないけど…カマンベール・ド・ノルマンディのレシピは、1日たってから、3日になる前に取り出すみたいだぞ」
  - 工房オリジナルの相棒は推定タイプの型、失敗種の相棒は「失敗種」の型
  - 型1／型2はカードNoと穴の番号で決める（同じヒントはいつも同じ言い方）
- 段階：うまれたては前に「…ん、ひらめいた。」を付ける（`stagePrefix`）。他の段階は前置きなし
- 吹き出しの見出しは「**{名前}のひらめき**」（例：「うちの子のひらめき」「もちこのひらめき」）。下に開いた穴のカードを小さく出し、タップで図鑑のそのカードへ飛ぶ
- 文は「ゲームのレシピ」として言う。「本物の◯◯は〜して作る」とは言わない（分岐表の△を事実として話さない。`ヒント設計_v1.md` §1-5）

### 5-3. 取り出したときのセリフの順
1. 何ができたか（新種なら「あたらしい子がうまれた！」）
2. 実在種：一言解説（本物の知識）→ 初めてのタイプなら「タイプのきほん」→ なかまのヒント
3. 失敗種：「{fail}って子がうまれたよ。{解説}んだって。」→ 初めてならねらいの穴を1つ
4. 工房オリジナル：「どのレシピにもない、きまぐれな子がうまれたよ（工房オリジナル。実在の銘柄ではありません）」
5. ねらいと違ったら近さのしるし（「あと1か所みたい！」等。どこが違うかは言わない）

## 6. 放置時の挙動（死なない・消えない）

| 放置期間 | 起きること | 戻ったとき |
|---|---|---|
| 6時間〜 | 機嫌が1時間2ずつ下がる・元気が下がる（下限10） | ふつうに操作すれば戻る |
| 24時間〜 | **すね**（背中を向ける・「…べつに待ってないし」） | なでる／話しかける2回で解除。「おかえり」演出＋再会ボーナス |
| 3日〜 | **ワイルド度1**（白いカビがふわっと増える） | お手入れ1回で戻る。図鑑ヒントのおみやげ |
| 7日〜 | ワイルド度2（もこもこ） | お手入れ2回で元通り |
| 14日〜 | ワイルド度3（もじゃもじゃ。これはこれで可愛い絵にする） | お手入れ3回で元通り。ワイルドアルバムに記録 |
| 30日〜 | 相棒から「手紙」が届いている演出（待っていた間の日記3行） | 「長いおでかけ、おかえり」イベント |

**しないこと**：死ぬ・腐る・消える・なつき度が減る・段階が戻る・図鑑が減る・開いたヒントが閉じる・課金で治す。放置の通知も**3日目と7日目の2回だけ**で、それ以降は送らない（罪悪感で引き戻さない。旅かえるの教訓）。

時計を戻す操作をされても罰はしない：経過時間がマイナスなら0として扱い、未来に進められた場合も熟成は最大14日扱いで止まるだけ。

## 10. 端末内保存とデータ構造

### 10-1. 保存の仕組み（技術判断・自律）
- 保存先：Capacitor Preferences（ネイティブ）／Web版は IndexedDB。**1つのセーブ文書（JSON）を書き換える方式**。操作のたびに保存（デバウンス1秒）
- オフラインの経過は「最後に保存した時刻」との差分で、起動時にまとめて計算する（機嫌・元気・ワイルド度・熟成の進み）
- 機種変更：Android の自動バックアップ（アプリデータを Google ドライブへ自動退避する OS 機能）と iOS の iCloud バックアップに乗せる。加えて**手動の書き出し／読み込み**（設定画面からJSONファイルを保存・共有）を用意。アカウントは作らない（2027年4月の復元要件はログイン付きアプリが対象）
- 写真（記念撮影・卒業証書）は端末の写真フォルダに保存し、セーブ文書にはメタ情報だけ持つ
- `schemaVersion` で版を管理し、読み込み時にマイグレーションする
- ヒント文そのものは保存しない（`hints.json` から毎回引く）。開いた穴は**穴のキー**だけ持つ
