## 分担
| 担当 | 仕事 |
|---|---|
| クラウド（Claude Code のプロジェクト） | `app/` の実装・テスト・PR |
| ローカル（チーズくん） | 絵の生成と費用管理・`art_tools`／`zukan_tools` の値の変更・絵とデータの書き出し |
| ローカル（d） | PR の検収（pull→テスト→Codex 監査）・master への反映判断 |
| オーナー | PR の最終承認・実機確認・お金が出る操作 |

## 絵
1. ローカルで生成（原本は `D:/claude/チーズ育成/art/`。リポジトリには入れない）
2. `art_tools/export_app_assets.py` で書き出す（体82種の 512px・1024px WebP、重ね絵・着せ替え・背景・アイコンなど）
3. 書き出した完成品だけを commit・push（置き場所は `app/public/assets/` の予定）
4. クラウドは pull して使う。**足りない絵・作り直してほしい絵は PR に「必要な絵」として書く**（クラウドでは描かない）
- 絵を差し替えたら同じファイル名で上書き。PWA のキャッシュは内容のハッシュで切り替える

## 図鑑データ
- 正本は `zukan_tools/data.py`。**数値を変えるのはローカル（チーズくん）だけ**
- 変えたら：`check.py`→`hint_gen.py --check`→`hint_gen.py`（hints.json を作り直す）→アプリ用の書き出し→`npm run test` を回してから push
- アプリ側は `app/src/data/generated/` の書き出し結果だけを読む。値を手で直さない
- 書き出し結果には元データの sha256 を入れ、`species.json` と `hints.json` の sha が違えばテストで止める

## 顔・着せ替えの数値
- `art_tools/face_style.json`・`faces.json`・`neck_calc.py` が正本。値を変えるのはローカルだけ
- 変えたら書き出し→顔の照合テスト（88通り・座標の差0.01未満）を回す

## PR の検収
1. クラウドが PR を出す（何を変えたか・どう確かめたか・必要な絵）
2. d がローカルで pull → テスト → Codex 監査
3. オーナー承認 → master へ反映。反映したら PR を見張らせたスレッドは閉じる
