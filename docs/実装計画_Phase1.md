## 0. 要約
- **作るもの**：Vite＋React＋TypeScript の1本のWebアプリを、そのまま PWA（Web版）と Capacitor の Android アプリにする。サーバーなし・ログインなし・端末内のセーブ文書（JSON）1本
- **ゲームの中身は「純粋な関数」で書き、React から切り離す**（判定・熟成・相棒の経過・ヒント）。テストは時刻を引数で渡して行う。オーナー確認用に**デバッグ版だけ「時間を進める」ボタン**を付ける（14日ものを待たずに試せる）
- **データは Python の正本から書き出す**：`data.py`（図鑑）・`hints.json`・`face_style.json`・`faces.json`・`ng_words_v1.txt` を、書き出しスクリプトでアプリ用 JSON にする。**87,360通りの判定は Python と TypeScript で全件一致を自動テスト**する
- **顔は face_parts.py を TypeScript に移植**し、体の絵（WebP）の上に SVG で重ねる。Python と同じ図形が出ることを88通り（8型×11表情）で自動照合する
- **工程は8週**。W4 で「チュートリアル〜8日目」を Web で通して遊べる、W5 でオーナーの Android 端末に入る、W7 でリリース候補、W8 でテスト配布と審査提出
- **Phase1 で作らないもの**：殿堂入り・飾り棚、ヴィンテージ（61日目）の切り替え演出、100日記念、30日の手紙、ウィジェット、iOS。どれも公開から30日以上たたないと誰も届かないので、**公開後のアップデート（v1.1・公開後2〜4週）**に回す
- **§7 の6点は決定済み**（2026-10-18 オーナー）：Play は組織アカウント登録済み／チュートリアルの最初の熟成だけ1分／初版は広告・課金なし／計測は Firebase Analytics／Android は GitHub Actions でビルド／ドメイン uchino-cheese.jp

## 2. データ構造

### 2-1. 端末内のセーブ文書（JSON 1本）
- 形は**相棒仕様 v2 §10-2 の schemaVersion 2 をそのまま初版にする**。足すのは下の4つだけ（v2 の項目は変えない）

| 足す項目 | 型 | 理由 |
|---|---|---|
| `meta.appVersion`・`meta.saveSeq` | 文字列・整数 | どの版で書いたか／保存ごとに1増やす（2つの保存場所のどちらが新しいかの判定） |
| `tutorial.step`・`tutorial.done` | 整数・真偽 | チュートリアル途中でアプリを閉じても続きから |
| `aging[].notifIds` | 整数の配列 | 熟成完了の通知を取り出し時に取り消すため |
| `notify.absenceScheduled` | 真偽 | 放置の通知（3日目・7日目）を起動のたびに付け替えるため |

- **保存の仕方**（技術判断・自律）
  - 保存場所の抽象化 `SaveStore`：ネイティブ＝`@capacitor/preferences`、Web＝IndexedDB（`idb-keyval`）。**同じ文書を2か所（A・B）に交互に書き**、読むときは壊れていない方のうち `saveSeq` の大きい方を使う（書き込み途中でアプリが落ちても1つ前に戻れる）
  - 操作のたびにデバウンス1秒で保存。アプリが裏に回る（`App` の pause）ときは即保存
  - 起動時：読む→`schemaVersion` を見て移し替え（`migrations/v1_to_v2.ts` …の鎖）→経過計算→保存
  - **自分より新しい版の文書を読んだ場合**（ダウングレード）は上書きしない読み取り専用モードで起動し、更新をうながす
  - 書き出し：設定から JSON ファイルを保存・共有（`@capacitor/filesystem`＋`@capacitor/share`／Web はダウンロード）。読み込みは形を検査してから置き換え（置き換え前の文書を自動で書き出しておく）
  - Android の自動バックアップ（Google ドライブ）に Preferences を載せる。Android 12 以降の `data_extraction_rules.xml` と旧来の `full_backup_content.xml` の両方を置く
- 派生値は保存しない：仕上げの解放状態（登録数から計算）、なつきLv（累計から `level_of`）、段階（日数から）

置き場所：`app/src/data/generated/`（書き出し結果をコミットする。先頭に元データの sha256 と書き出し日時）

## 3. 技術の選定と理由
フォルダ：リポジトリ uchino-cheese の `app/`（ローカルは `D:/codex/チーズ育成/app/`。作業はブランチ、master＝本番、PR で出す）

| 項目 | 選ぶもの | 理由 | 採らなかったもの |
|---|---|---|---|
| 土台 | **Vite＋React 18＋TypeScript**（静的ファイルを出すだけ） | Capacitor は静的な出力をそのまま包む。SSR が要らない。社内で React の資産がある。**Vite はシンボリックリンクを使わないので D:（exFAT）で動く見込み**（W1 で `npm install`・`vite build`・`cap sync` を実測） | Next.js：静的書き出しでも使えるが、D: の exFAT では Turbopack／本番ビルドが落ちる（ぬいぐるみナビで実測）。このアプリにサーバー機能は不要 |
| 状態 | **Zustand**（ストア1つ）＋**ゲームの中身は純粋な関数**（`src/game/`：judge・aging・buddy・hints・names・time） | 状態はセーブ文書1本なので大きな仕組みは不要。関数は `(state, now) → state` にして React から切り離し、時刻を引数で渡してテストする | Redux（重い）、React の useReducer だけ（画面をまたぐ受け渡しが面倒） |
| 時刻 | `src/game/time.ts` に集約（日付の切り替え＝端末のローカル時刻4時・経過は分単位の整数） | テストで時刻を差し替える／デバッグ版の「時間を進める」を1か所で実現 | 各所で `Date.now()` を直接呼ぶ |
| 保存 | `@capacitor/preferences`（ネイティブ）／`idb-keyval`（Web）、A・B交互書き | §2-1 | localStorage（Web で容量・消去の扱いが弱い） |
| 通知 | `@capacitor/local-notifications`。朝・夜（1日2通まで）＋熟成完了（取り出しの窓に入った時刻）＋放置（3日目・7日目だけ）。**正確なアラームの権限は使わない**（Android 14 以降は既定で拒否・Play の規程でも時計アプリ向け）。数分の遅れは許容 | 相棒v2 §7。Android 13 以降は通知の許可（POST_NOTIFICATIONS）をチュートリアル⑥で取る | Web版：サーバーなしでは予約通知を出せないので、**Web版は通知なし**（アプリ内の表示だけ）。プッシュ通知（サーバー・アカウントが要る）は使わない |
| 顔 | **face_parts.py を TypeScript に移植**（`src/face/shapes.ts`）。React で SVG を描く。体の絵は同じ SVG の `<image>`、顔は `faces.json` の `cx・cy・w・tilt` で置く。線の太さは `13×1000÷w`（Python と同じ式） | 型8×表情11を1本のコードで描ける。まばたき・口パクは表情の差し替え（タイマー）、ぴょこんと跳ねる等は CSS の transform | 88枚の SVG ファイルを置く方式：体ごとの線の太さの換算ができない |
| 重ね絵 | SVG の `<mask>`（体の画像のアルファで切る）で産毛・ひび・ワイルド度を体の形に切る。ヴィンテージの色は SVG フィルター（`feColorMatrix`）で `vintageTone`（乗算920‰・彩度1100‰）を再現 | Python の extras_lib と同じ考え方。表示中に重ね方を変えられる | 重ねた絵を種ごとに書き出す（82種×段階×ワイルド度で点数が爆発） |
| 記念撮影 | Canvas で合成（体→重ね絵→顔の SVG を画像化して描く→文字）。文字は**同梱の日本語フォント**（OFL など商用可。候補：Zen Maru Gothic／M PLUS Rounded 1c。W1 で字の数と容量を見て決める） | 相棒v2 §4：名前は同梱フォントに字があるものだけ通す（ビルド時にフォントの字の一覧を作る） | 端末のフォント任せ（機種で「□」になる） |

**D:（exFAT）の注意点**
1. シンボリックリンク・ジャンクションが使えない → pnpm・Prisma・Turbopack は使わない。npm を使う（Windows の npm はリンクでなく `.cmd` を作る）

## 8. 危ないところ（先に書いておく）
| リスク | 起きたら | 先にやること |
|---|---|---|
| D:（exFAT）でビルドが落ちる | ビルドだけ C: の作業場所で行う | W1 の初日に実測 |
| Play の対象 API レベルの要件 | 古い Capacitor だと提出できない | W1 で Play の現行要件を確認し、それを満たす Capacitor の版を使う |
| 低スペック機で重い（SVG の顔＋重ね絵） | 顔と重ね絵を一度画像にしてから表示する方式に切り替え | W5 で実機の起動時間・操作の反応を測る |

| 図鑑データの直し（裏取りの追加など）とアプリの食い違い | 書き出し→テストで止まる | sha の照合（§2-3） |
